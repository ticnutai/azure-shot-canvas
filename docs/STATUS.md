# מצב הפרויקט — אולפן צילום מסך (אורום סטודיו)

> עמוד זה מיועד לכל מפתח שנכנס לפרויקט: מה התוכנה, איפה היא עומדת, איך עובדים עליה ומה כדאי לעשות הלאה.
> עודכן: 21 באוקטובר 2026 · הגרסה האחרונה שפורסמה: **0.19.0**

---

## 1. מה זה

תוכנה לשולחן העבודה של חלונות, כולה בעברית, לצילום מסך ולהקלטת מסך — בסגנון התוכנות המובילות בתחום.
הכל רץ במחשב המשתמש: אין שרת, אין חשבון, אין העלאה לענן. הקבצים נשמרים בתיקייה מקומית.

היכולות העיקריות (הרשימה המלאה ב[קובץ ההסבר הראשי](../README.md)):

- **צילום:** אזור, חלון, מסך מלא, עמוד גלילה אוטומטי, האזור הקודם, טקסט מאזור (זיהוי טקסט מקומי בעברית ובאנגלית), קריאת קודים מרובעים, מידות מדויקות במספרים.
- **הקלטה:** מסך, חלון או אזור, עם קול מערכת ומיקרופון, השהיה, מסגרת וסרגל צף שלא נכנסים להקלטה, הצגת קיצורי מקשים בהקלטה.
- **סימון ועריכה:** סימון מהיר על המסך הקפוא, עורך תמונות מלא (השחרה חכמה, זרקור, מדידה, ייצוא מעוצב), עורך וידאו עם ציר זמן.
- **סרגל עליון צף:** לשונית דקה בקצה המסך שנפתחת בנגיעה, עם כפתורי צילום והקלטה.
- **לוח הצילומים:** חלון עם הצילומים האחרונים, תצוגות, תיקיות, מקשי קיצור, העתקת כמה צילומים יחד, מדריך צעדים, חיתוך וידאו. אפשר להסתיר אותו בקצה המסך, ואפשר לפצל אותו לשני חלונות (רשימה וכפתורים).
- **עדכונים אוטומטיים** ממאגר ציבורי של קובצי התקנה.

## 3. מבנה התוכנה בקצרה

התוכנה בנויה על מעטפת שולחן העבודה של כרומיום (Electron): תהליך ראשי אחד ומספר חלונות.

| קובץ | תפקיד |
|---|---|
| `src/main.cjs` | התהליך הראשי: חלונות, קיצורים, צילום, שמירה, מגש, עדכונים, כל ההודעות בין החלונות |
| `src/index.html` + `src/renderer.js` | חלון האולפן הראשי (צילום, הקלטה, ספרייה, הגדרות, עורכים) |
| `src/quickbar.*` | הסרגל העליון הצף והכרטיס שאחרי צילום |
| `src/workspace.*` | לוח הצילומים. אותו דף משמש גם לחלון הכלים כשהלוח מפוצל (`?part=tools`) |
| `src/dock-panel.cjs` | חלק משותף: חלון חופשי או מוסתר בקצה המסך, נעיצה, גרירת הלשונית ושמירת המקום. גם הלוח וגם חלון הכלים בנויים ממנו |
| `src/region-*` | שכבת הבחירה על המסך הקפוא, הסימון המהיר והמידות |
| `src/image-editor.*`, `src/editor-*` | עורך התמונות וסרגל הכלים הגמיש. המנוע נבנה לקובץ `editor-engine.js` (`npm run editor:build`) |
| `src/window-list.cjs` | עוזר קבוע ברקע (חלון פקודות מוסתר עם קוד מהודר) לרשימת חלונות, צילום מהיר, גלילה ולכידת מקשים |
| `src/features-defs.js` + `src/features-ui.js` | **תוספות אופציונליות:** טבלה אחת (שם, הסבר, הגדרות) שממנה נבנים הלשונית "תוספות" בהגדרות, הקובץ השמור והבדיקות. כל תוספת כבויה עד שמדליקים אותה. מצב התוספות נשמר ב־`features.json` |
| `src/interval-capture.cjs`, `src/text-index.cjs`, `src/pin-window.cjs`, `src/translate-local.cjs`, `src/click-ripple.js`, `src/settings-backup.cjs` | הלוגיקה של כל תוספת בקובץ משלה, בלי תלות בחלונות, כדי שאפשר לבדוק אותה בבדיקות קטנות |
| `src/png-encode.cjs` | שמירת תמונה בתהליכון רקע כדי שהמסך לא ייתקע |
| `src/updater.cjs` | עדכונים אוטומטיים |
| `*-utils.cjs` | חישובים טהורים שנבדקים בבדיקות קטנות |

הגדרות המשתמש נשמרות בתיקיית הנתונים של התוכנה (`%APPDATA%\hebrew-screen-studio`), למשל `quickbar-preferences.json`, `workspace-window.json`, `workspace-tools.json`.

## 4. איך עובדים

```powershell
npm install
npm start              # התוכנה מתוך הקבצים, עם רענון אוטומטי
npm test               # הבדיקות הקטנות (98)
npm run test:e2e       # בדיקות מלאות על התוכנה עצמה (96, כחצי שעה)
npm run dist           # בניית קובץ התקנה לתיקייה dist
```

כללי עבודה שנקבעו:

1. **בלי כפילויות.** לפני שמוסיפים כפתור, פעולה או מנגנון — לבדוק אם כבר קיים, ולהשתמש בו. דוגמאות: טבלת מקשים אחת שמזינה גם את הטיפול במקשים וגם את חלון העזרה; חלק אחד להסתרה בקצה המסך לשני חלונות.
2. **כל שינוי עם בדיקה.** בדיקות ממוספרות לפי שלבים, כך שרואים בדיוק מה נשבר.
3. **בזמן הפיתוח מריצים רק את הבדיקות הקשורות לשינוי**, ולפני בניית גרסה — הרצה מלאה אחת.
4. **בדיקות לא מקפיצות חלונות** מעל עבודת המשתמש: הבדיקות רצות במצב מוסתר, ובדיקה של התוכנה המותקנת נעשית דרך פתחת ניפוי (`SCREEN_STUDIO_DEBUG_PORT`, `scripts/cdp.cjs`).
5. **כל הממשק בעברית**, כולל הודעות שגיאה. גם הודעות השמירה בגיט בעברית.
6. **לפני בנייה לשינוי עיצובי** — מציגים למשתמש קודם (צילומים או הפעלה מקומית) ורק אחר כך בונים.

### פרסום גרסה

1. הרצה מלאה של כל הבדיקות.
2. עדכון `version` בקובץ `package.json`, שמירה ושליחה.
3. `npm run dist` — נוצרים בתיקייה `dist` קובץ ההתקנה, קובץ החלקים (`.blockmap`) ו־`latest.yml`.
4. יצירת גרסה במאגר `aurum-screen-studio-releases` עם שלושת הקבצים (`gh release create`). בלי שלושתם העדכון האוטומטי לא יעבוד.
5. התקנה שקטה במחשבים: `Aurum-Screen-Studio-Setup-X.Y.Z.exe /S`.

### תוספות אופציונליות (מגרסה 0.19.0)

כל אחת מתג בהגדרות ← "תוספות", כבויה כברירת מחדל, וכשהיא כבויה היא לא רצה ולא צורכת כלום:

| תוספת | מה היא עושה |
|---|---|
| חיפוש טקסט בתוך הצילומים | זיהוי טקסט ברקע, פעם אחת לכל תמונה, ושמירתו ליד התמונה; החיפוש בלוח הצילומים מוצא גם מילים שבתוך התמונה. נעצר בזמן הקלטה |
| פעולה נפרדת לכל קיצור | לכל סוג צילום (מסך מלא, אזור, גלילה) פעולה משלו אחרי השמירה |
| הצמדה משופרת | גלגלת משנה גודל, קונטרול + גלגלת משנה שקיפות, לחיצה כפולה מאפסת; הצמדת מה שבלוח (תמונה, טקסט, צבע) |
| אפקט לחיצה בהקלטה | טבעת מתרחבת בכל לחיצת עכבר, בצבע לבחירה |
| צילום אוטומטי במרווחים | צילום המסך או האזור האחרון כל כמה שניות, עד מספר שנקבע או עד עצירה |
| תרגום טקסט מצילום | אחרי "העתקת טקסט מאזור", ההעתקה היא התרגום; נעשה במנוע שפה מקומי בלבד (כתובת מקומית בלבד), בלי רשת |

בנוסף, בלשונית עצמה: **גיבוי והחזרת הגדרות** לקובץ אחד. הקלטה כתמונה נעה (GIF) כבר הייתה קיימת, לכן לא נוספה.

## 6. מצב נוכחי

- **יציב ומותקן** במחשב הראשי (0.19.0). במחשב JJ מותקנת 0.17.0 — החיבור מרחוק אליו היה כבוי, והוא יתעדכן לבד כשהתוכנה תיפתח בו.
- **בדיקות:** 138 בדיקות קטנות ו־108 בדיקות מלאות (כולן עברו לפני 0.19.0). בהרצה מלאה על מחשב עמוס יש לפעמים 1–2 כשלים בזמנים (הקלטה, זיהוי טקסט) שעוברים בהרצה חוזרת.
- **צריכת משאבים במנוחה:** המעבד וכרטיס המסך כמעט אפס; זיכרון כ־430–550 מגה (כ־120 פחות כשהתצוגה החיה כבויה).
- **הקלטה:** כ־9% מליבה אחת של המעבד.

### בעיות ידועות

- בדפדפן (מצב הפיתוח בלי המעטפת) חלונות מסרב לפעמים לצילום מסך עד הפעלה מחדש של המחשב. בתוכנה עצמה זה לא קורה.
- חלונות לא נותן לחלון רחב פחות מ־41 נקודות; הלשונית המקופלת נחתכת לצורתה (`setShape`) כדי שזה לא ייראה.
- המאגר הישן `azure-shot-canvas` עדיין ציבורי ומכיל את הקוד — ייסגר לפרטי אחרי שכל המחשבים יעברו לגרסה שמתעדכנת מהמאגר החדש.

## 7. המלצות להמשך

לפי סדר עדיפות:

0. **לנסות את התוספות בשימוש אמיתי** ולהחליט אילו להשאיר ואילו להרחיב: בפרט אפקט הלחיצה (נבדק בבדיקות ובציור, אבל לא בלחיצת עכבר אמיתית) והתרגום (נבדק מול מנוע מדומה, ולא מול מודל אמיתי).
1. **לסגור את המאגר הישן לפרטי** אחרי ש־JJ יתעדכן (Lovable ממשיך לעבוד גם עם מאגר פרטי).
2. **לייצב את 2 הבדיקות שנכשלות לפעמים** בהרצה מלאה (הקלטה וזיהוי טקסט) — להאריך המתנות או להריץ אותן בנפרד.
3. **לפרק את `src/main.cjs`** (כ־2,000 שורות) לקבצים לפי נושא: חלונות, צילום, הקלטה, הודעות. כבר התחלנו: `dock-panel.cjs`, `png-encode.cjs`, `key-overlay.cjs`.
4. **חתימה דיגיטלית לקובץ ההתקנה** — כדי שחלונות לא יציג אזהרת "מפרסם לא ידוע".
5. **קישור שיתוף לצילום** ו**תרגום טקסט מצילום** — דורשים שירות ברשת ובחירה של המשתמש איזה.
6. **הקלטה דרך כרטיס המסך** — נמדד: חוסך רק כ־6.5% מליבה אחת, עם שינוי גדול וסיכון. נדחה; לחזור אליו רק אם יתבקשו הקלטות ארוכות במחשבים חלשים.
7. **לעדכן את קובץ ההסבר הראשי** — חלק מהרשימה שם נכתב לפני גרסה 0.14 ויש בו מונחים לא עדכניים.

## 8. נקודות פתיחה למפתח חדש

- להתחיל ב־`src/main.cjs` (חיפוש `ipcMain.handle` נותן את כל הפעולות שהחלונות יכולים לבקש).
- כל תכונה חדשה של ממשק — לחפש קודם בדיקה קיימת ב־`tests/e2e` באותו תחום ולהוסיף לה שלב.
- מצב בדיקה: משתני הסביבה `SCREEN_STUDIO_QA=1` (חלונות מוסתרים, נקודות בדיקה ב־`globalThis.__aurumQa`) ו־`SCREEN_STUDIO_HEADLESS=1`.
- הנחיות קבועות לעבודה עם הפרויקט נמצאות ב־`AGENTS.md`.
